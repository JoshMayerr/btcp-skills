# Input intake and provenance

Preserve every source unchanged; work from copies or read-only source tabs and record hashes when feasible. Inventory each file's type, usable contents, date coverage, grain, units, currencies, identifiers, version, and apparent owner.

Build a source register with file name, file type, source classification, relevant date/period, population, limitations, supported analyses, and whether management-provided, public, inferred, or synthetic. Provenance does not prove every field: an export is management-provided evidence, while its business interpretation may remain a management claim.

Map requested outputs to evidence and mark each supported, partially supported, or unsupported, explaining missing inputs and consequences. Start an open-item log with question, reason, affected analysis, owner, priority, status, and resolution evidence.

Check for unreadable/password-protected material, duplicated or conflicting versions, hidden/missing sheets, stale extracts, partial periods, sensitive data, mixed units/currencies, and ambiguous date meanings (service, invoice, booking, signature, go-live, cash). Never silently normalize source tabs; put transformations in governed mapping/calculation layers with source IDs and exception flags.

Before substantive work, summarize available evidence, executable analyses, caveated analyses, and blocked analyses.
